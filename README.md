# AutoPartsLink — Admin · Supplier · Customer app

**Live demo:** https://autopartslink-c896d.web.app

One Flutter app (Android, iOS and web), three role-based interfaces, backed by
**Firebase** — Firebase Authentication for accounts and Cloud Firestore for data.

## Architecture

```
      ┌──────────────┐   ┌──────────────┐   ┌────────────────┐
      │  Admin UI    │   │ Supplier UI  │   │  Customer UI   │
      └──────┬───────┘   └──────┬───────┘   └───────┬────────┘
             └──────── one Flutter app ─────────────┘
               screens → providers → repositories → services
                                 │
            ┌────────────────────┴─────────────────────┐
            │ Firebase Auth         Cloud Firestore     │
            │ (email + password)    + firestore.rules   │
            └───────────────────────────────────────────┘
```

After login, the user's `role` (ADMIN / SUPPLIER / CUSTOMER), stored in
`users/{uid}`, decides which home screen they see. **`firestore.rules` enforces
every permission server-side** — hiding a button in the UI is never the only
protection.

### Firestore data model

| Collection | Document ID | Holds | Who can read |
|---|---|---|---|
| `users` | Auth UID | role, isApproved, isActive, contact details, customer profile | the user, admins |
| `suppliers` | Auth UID | public business profile / directory entry | any signed-in user |
| `procurementRequests` | auto | vehicle, parts needed (`items[]`), urgency, status | owner customer, suppliers, admins |
| `quotations` | `{requestId}_{supplierUid}` | priced lines (`items[]`), fulfilment days, status | that supplier, the request's customer, admins |
| `orders` | same as quotation ID | items (price snapshot), fulfilment, `statusHistory[]` | its customer & supplier, admins |
| `ratings` | same as order ID | score 1–5 + optional review | any signed-in user |
| `notifications` | auto | recipientId, event, message, isRead | the recipient |

The deterministic IDs are how the rules enforce "one quotation per supplier per
request", "one order per quotation" and "one rating per order".

### Workflow
1. **Customer** creates a procurement request → all approved suppliers get a notification.
2. **Supplier** (once approved by an admin) submits a quotation → customer is notified.
3. **Customer** accepts one quotation → an order is created, the other quotations are
   rejected, and the request moves to `ORDER_CREATED` (all in one Firestore transaction).
4. **Supplier** moves the order through its statuses → customer is notified at each step.
5. **Customer** rates the supplier once the order is `COMPLETED`.

## Setup

### 1. Create the Firebase project
1. In the [Firebase console](https://console.firebase.google.com), create a project.
2. **Authentication → Sign-in method** → enable **Email/Password**.
3. **Firestore Database** → create a database (production mode).

### 2. Link the app to it
```bash
npm install -g firebase-tools        # Firebase CLI
dart pub global activate flutterfire_cli
firebase login

cd flutter_app
flutterfire configure                # pick your project; select android + ios
```
`flutterfire configure` overwrites the placeholder `lib/firebase_options.dart` and
adds `google-services.json` / `GoogleService-Info.plist`. The app throws
"Firebase isn't configured yet" on startup until you've done this.

### 3. Deploy the security rules and indexes
```bash
cd flutter_app
firebase use --add                   # choose the same project
firebase deploy --only firestore:rules,firestore:indexes
```

### 4. Run
```bash
cd flutter_app
flutter pub get
flutter run                          # with an emulator/device connected
```
iOS builds need macOS with Xcode.

### 5. Create the first admin
There's no public admin sign-up. Register a normal account in the app, then in the
Firebase console open **Firestore → users → {that user's UID}** and change `role`
to `ADMIN`. Log out and back in.

## App structure
```
flutter_app/
  firestore.rules               # server-side permissions + business rules
  firebase.json                 # Firebase CLI config (rules/indexes)
  lib/
    firebase_options.dart       # generated by `flutterfire configure`
    core/                       # collection names, session, error mapping, theme
    models/                     # Firestore map <-> Dart
    services/                   # Firebase Auth + Firestore reads/writes/transactions
    repositories/               # thin layer the providers depend on
    providers/                  # ChangeNotifier app state
    screens/                    # auth, admin, supplier, customer, common
```

## Notes
- Sign-in is by **email**; the "username" entered at registration is a display name.
- Deactivating a user blocks them at login and in `firestore.rules`. Disabling the
  Firebase Auth account itself needs the Admin SDK (e.g. a Cloud Function).
- Supplier search and the rating averages run client-side / via aggregate queries,
  which is fine at this project's scale.
